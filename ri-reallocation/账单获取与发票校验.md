# 账单获取与发票校验

`download_and_validate_billing.py` 使用 Azure **Consumption Usage Details API**
分别获取 `ActualCost` 和 `AmortizedCost`，使用 **Billing Invoices API** 获取发票
及金额，并校验实际账单与发票。输出 CSV 可直接作为 RI 分摊流水线输入。

> 按本工具需求使用 Consumption API，不自动切换数据源。微软已不推荐 EA/MCA
> 新增此 API 依赖，并计划停用；若账户已不支持或没有权限，脚本会明确失败，
> 不会把失败当作空账单。大规模账单建议后续迁移 Cost Details API 或 Exports。

## 运行

在 `ri-reallocation/` 目录安装现有依赖并登录 Azure：

```bash
python3 -m pip install -r requirements.txt
az login

python3 download_and_validate_billing.py \
  --billing-account-name "<完整-billing-account-name>" \
  --billing-profile-name "<billing-profile-name>" \
  --start-date 2026-08-01 \
  --end-date 2026-08-31 \
  --download-invoices \
  --output-dir billing-download
```

需要目标账单范围的成本明细读取权限及发票读取/下载权限（例如对应范围的 Billing
Reader；具体依协议类型而定）。订阅 Reader 并不自动拥有 Billing Account 发票权限。
MCA/MPA 推荐使用完整 Billing Profile 范围，不能用某个订阅的费用对整张发票。
参数填写资源名称，不是 ARM 资源路径；账户名称可能包含冒号和协议日期后缀。
默认连接 Azure 公有云，凭据来自当前 `az login`，不接收或保存访问令牌。

默认 `--usage-schema modern`，日期通过 `startDate/endDate` 传入 Usage Details。
EA 等 legacy 返回格式可显式指定 `--usage-schema legacy`，并省略 Billing Profile；
此时使用 `properties/usageStart`、`properties/usageEnd` 日期过滤，映射 `cost` 为
`costInBillingCurrency`。实际返回的 `kind` 必须与所选格式一致，防止误读金额。
Legacy 数据若不提供 `invoiceId`，完整性校验会失败，**不会根据日期猜测或补齐 ID**。
此脚本不提供订阅级 MOSP 发票获取。

Usage 日期范围与发票列表日期范围是两个独立概念。发票列表默认使用相同日期，
可以用 `--invoice-start-date` / `--invoice-end-date` 调整传给 Billing API 的
`periodStartDate/periodEndDate`。实际账单可能包含其他账期发票的费用，或延迟入账；
看到未知发票 ID / 发票缺少实际明细时，应检查两个范围是否覆盖完整账单。
不要为了“通过”而筛掉未匹配明细。当前工具按指定范围对账，不保证任意自然月等于
完整发票账期；必须使用已出账、范围完整的数据。

## 校验口径

金额使用 `Decimal` 原始精度累加，默认绝对容差为账单币种的 `0.01`，
通过 `--tolerance` 修改。先逐发票、逐币种检查，再检查各币种总额，
不同发票的正负差异不能互相抵消，不同币种不混加。

| 校验 | 规则 |
|---|---|
| 发票金额 | 默认使用税前 `subTotal` 对比 Actual 的 `costInBillingCurrency`，不使用付款后余额 `amountDue` |
| 其他金额口径 | 可显式选择 `--invoice-amount-field totalAmount` 或 `billedAmount`；直接比较该值，不隐式减税、加税或调整信用额 |
| 发票 ID 完整性 | Actual 所有行（含零费用行）的 `invoiceId` 非空，且能精确匹配所获取发票的 `name` |
| 反向覆盖 | 所获取每张发票都必须有 Actual 行，零金额发票也不会凭空通过 |
| 其他失败条件 | 空数据集、金额不匹配、币种不匹配；非法/缺失金额和币种、重复记录 ID/发票名、错误 API 结构会直接报错 |

`taxAmount`、`totalAmount`、`billedAmount`、`amountDue` 同时保留在报告中供核对。
费用明细一般不含税，因此含税总额通常不能直接匹配；税、信用额、预付款、
Marketplace、非 Azure 产品、退款或重开发票均可能导致差异。脚本保留负数费用，
不会删除退款、筛选 VM/RI 或自动“修正”差异。

Amortized 仅下载和按币种汇总，不要求其合计等于发票，也不检查其 `invoiceId`；
RI 摊销会改变各月成本表示。

## 输出与退出码

为避免旧成功报告或历史 CSV 混入，本次输出目录**必须不存在**。
推荐每次指定新的账期/运行目录；不要将目录设为已有原始数据目录。

```text
billing-download/
├── request.json
├── Actual.json
├── Amortized.json
├── actual/Actual_2026-08-01_2026-08-31.csv
├── amortized/Amortized_2026-08-01_2026-08-31.csv
├── invoices.json
├── invoice-id-issues.csv
├── invoice-reconciliation.csv
├── validation-summary.json
└── invoice-documents/       # 指定 --download-invoices 时
    ├── index.json          # 发票 ID 到本地文件名的映射
    └── invoice-0001.pdf
```

原始 JSON 保留 API 字段；小数序列化为字符串以避免二进制浮点精度损失。
CSV 保留 Usage properties，展开 `meterDetails`、序列化 tags，并提供流水线所需
`ResourceId`、`costInBillingCurrency`、`billingCurrency` 等字段。
Modern 返回的 `instanceName` / `subscriptionGuid` 同时映射为
`ResourceId` / `subscriptionId`，`costInUSD` 映射为 `costInUsd`。
发票记录总是保存到 `invoices.json`；`--download-invoices` 额外下载每张发票的默认
文档（PDF 或 ZIP，按内容确定扩展名），并非逐个下载全部税务附件。
下载 URL 生成支持 202 轮询，
`--invoice-download-timeout` 默认 600 秒；单次 HTTP 请求超时为 120 秒。
429/部分 5xx 最多请求 5 次，其他 API 错误直接抛出。
重试同时遵守 `Retry-After` 和 Consumption 的
`x-ms-ratelimit-...-retry-after` 秒数，取最大等待值；超过 600 秒时明确报错，
避免提前重试导致持续限流。

`invoice-id-issues.csv` 给出 Actual CSV 行号（含表头）、原始记录 ID、
缺失/未知发票 ID、币种和金额；`invoice-reconciliation.csv` 给出逐发票差额。
`validation-summary.json` 包含总体结论、币种汇总、空数据集以及未匹配发票。
报告出现 `passed: true` 才表示本次两项校验成功。

退出码：`0` 表示校验通过，`2` 表示完成下载但校验不通过（命令行参数错误也使用
`2`）；网络、认证、数据格式或文件操作异常非零退出并显示异常。
校验不通过仍保留全部已下载数据和差异报告；中途下载/解析失败可能留下部分文件，
但不会生成本次最终 `validation-summary.json`，不能据部分文件继续分摊。
这些文件包含敏感账单信息；默认 `billing-download/` 已被 Git 忽略，自定义输出目录
也应放在仓库外或自行加入 ignore，不要提交账单或上传给无权限人员。

校验通过后接入第一步：

```bash
python3 allocate_ri_difference.py \
  --actual "billing-download/actual/Actual_*.csv" \
  --amortized "billing-download/amortized/Amortized_*.csv" \
  --output-dir work/01-actual-reconciled
```
