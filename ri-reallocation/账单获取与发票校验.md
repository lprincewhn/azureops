# 账单获取与发票校验

`download_and_validate_billing.py` 默认使用 Azure **Cost Details Report API**
分别获取 `ActualCost` 和 `AmortizedCost`，使用 **Billing Invoices API** 获取发票
及金额，并校验实际账单与发票。输出 CSV 可直接作为 RI 分摊流水线输入。

> 默认 `--usage-source cost-details`：服务端生成 CSV，客户端下载所有分片并逐行
> 对账，不再通过 Consumption 分页获取费用明细。仅显式指定
> `--usage-source consumption` 时使用旧接口；不会在失败后自动回退或切换数据源。

## 运行

在 `ri-reallocation/` 目录安装现有依赖并登录 Azure：

```bash
python3 -m pip install -r requirements.txt
az login

python3 download_and_validate_billing.py \
  --billing-account-name "<完整-billing-account-name>" \
  --billing-profile-name "<billing-profile-name>" \
  --start-date 2026-08-01 \
  --end-date 2026-08-31 \
  --download-invoices \
  --output-dir billing-download
```

需要目标账单范围的成本明细读取权限及发票读取/下载权限（例如对应范围的 Billing
Reader；具体依协议类型而定）。订阅 Reader 并不自动拥有 Billing Account 发票权限。
MCA 推荐使用完整 Billing Profile 范围，不能用某个订阅的费用对整张发票。
参数填写资源名称，不是 ARM 资源路径；账户名称可能包含冒号和协议日期后缀。
默认连接 Azure 公有云，凭据来自当前 `az login`，不接收或保存访问令牌。

Cost Details Report 使用 `2025-03-01` API 版本，分别 POST
`metric: ActualCost` / `AmortizedCost` 和 `timePeriod: {start, end}`，
遵循 `Location`、`Retry-After` 轮询报告。初次请求直接返回结果也支持。
`--cost-details-timeout` 默认为 1800 秒，按每种 metric、每个日期分段限制生成及轮询
等待；该参数不限制整个批次和所有文件的下载总时长。

官方支持范围主要为 EA/MCA。EA 可省略 Billing Profile，其他协议需确认服务支持；
权限不足或不支持时直接报错，不会当作空账单。每份报告最多一个月，脚本自动沿
自然月边界拆分跨月请求，不重叠、不遗漏日期，再分别合并 Actual 和 Amortized。
API 通常仅提供当前月之前最多 13 个月的历史数据，过早日期由服务端拒绝。
月数据超过约 2 GB / 200 万行时，微软建议使用 Exports。

费用明细若不提供 `InvoiceId`（例如 EA），完整性校验会失败，
**不会根据日期或发票列表猜测、补齐 ID**。此脚本不提供订阅级 MOSP 发票获取。

费用明细日期范围与发票列表日期范围是两个独立概念。发票列表默认使用相同日期，
可以用 `--invoice-start-date` / `--invoice-end-date` 调整传给 Billing API 的
`periodStartDate/periodEndDate`。实际账单可能包含其他账期发票的费用，或延迟入账；
看到未知发票 ID / 发票缺少实际明细时，应检查两个范围是否覆盖完整账单。
不要为了“通过”而筛掉未匹配明细。当前工具按指定范围对账，不保证任意自然月等于
完整发票账期；必须使用已出账、范围完整的数据。

## 校验口径

金额使用 `Decimal` 原始精度累加，默认绝对容差为账单币种的 `0.01`，
通过 `--tolerance` 修改。先逐发票、逐币种检查，再检查各币种总额，
不同发票的正负差异不能互相抵消，不同币种不混加。

| 校验 | 规则 |
|---|---|
| 发票金额 | 默认使用税前 `subTotal` 对比 Actual 的 `costInBillingCurrency`，不使用付款后余额 `amountDue` |
| 其他金额口径 | 可显式选择 `--invoice-amount-field totalAmount` 或 `billedAmount`；直接比较该值，不隐式减税、加税或调整信用额 |
| 发票 ID 完整性 | Actual 所有行（含零费用行）的 `invoiceId` 非空，且能精确匹配所获取发票的 `name` |
| 反向覆盖 | 所获取每张发票都必须有 Actual 行，零金额发票也不会凭空通过 |
| 其他失败条件 | 空数据集、金额不匹配、币种不匹配；非法/缺失金额和币种、重复发票名、错误 API 结构会直接报错 |

`taxAmount`、`totalAmount`、`billedAmount`、`amountDue` 同时保留在报告中供核对。
费用明细一般不含税，因此含税总额通常不能直接匹配；税、信用额、预付款、
Marketplace、非 Azure 产品、退款或重开发票均可能导致差异。脚本保留负数费用，
不会删除退款、筛选 VM/RI 或自动“修正”差异。

Amortized 仅下载和按币种汇总，不要求其合计等于发票，也不检查其 `invoiceId`；
RI 摊销会改变各月成本表示。
脚本保留报告所有分片的所有费用行，不按 `usageDetailId` 去重。
Cost Details CSV 通常没有独立行 ID，因此该列使用 metric/日期段/分片文件/记录行号
作为定位标识，不是 Azure 生成的 ID；异常 CSV 的 `csvRow` 仍指向最终 Actual CSV
中的记录行号（含表头，多行字段按一条记录计数）。

## 大账单与内存

Cost Details 的所有 `manifest.blobs` 按顺序以 1 MiB 分块下载到 `.part` 文件，
核对各分片字节数后改名为 `.csv`，然后逐行解析和汇总。清单中的分片数、总字节数、
重复链接也会检查，不会只读取第一片。异常直接写入 CSV，不在内存中保留整月明细。
发票 PDF/ZIP 同样分块下载。内存主要取决于缓冲区、单行大小、发票列表及不同
发票/币种的汇总数量，而不是全部费用行数；并非严格固定内存上限。

目前 Cost Details 文档没有服务端压缩开关，本实现接收 `dataFormat: Csv`、
`compressData: false`；遇到其他格式明确报错，不猜测压缩类型。
原始分片和最终 CSV 均未压缩。低内存来自流式处理，而不是压缩。
需要服务端 gzip 压缩时应另用 Exports，本脚本不会创建 Storage 或 Export 资源。

为保留后续分片才出现的 CSV 字段，每种账单的规范化 CSV 单元格先写入输出目录内的
临时磁盘文件，获取完整列集合后再逐行生成最终 CSV；临时文件随后自动关闭清理。
请为原始 CSV 分片、最终 CSV 及一份账单的临时数据预留磁盘空间。最终 CSV 在对应明细流消费
完成后生成；最终完成状态仍以 `validation-summary.json` 为准。

### 旧 Consumption 兼容模式

显式指定 `--usage-source consumption` 可保留旧数据源及 `Actual.json` /
`Amortized.json` 输出。`--usage-schema modern`（默认）使用 `startDate/endDate`；
`--usage-schema legacy` 使用 `properties/usageStart`、`properties/usageEnd`
日期过滤，映射 `cost` 为 `costInBillingCurrency`，并要求返回 `kind` 匹配。
`--usage-schema legacy` 不能与默认 Cost Details 模式混用。
Consumption 分页逐行写原始 JSON；重复的 `nextLink` 仍会报错，费用行不去重。
原来的全量列表接口 `AzureAPI.list()` / `normalize_usage()` 仍可供小数据调用者使用，
但会物化全部记录；自定义下载封装应使用 `iter_list()` / `iter_normalize_usage()`。
仅覆盖 `list()` 不会拦截费用下载。自定义 `request()` 封装如需支持 Cost Details，
还须支持新的关键字参数 `body`（JSON 请求体）与 `deadline`（轮询截止时间）。

## 输出与退出码

为避免旧成功报告或历史 CSV 混入，本次输出目录**必须不存在**。
推荐每次指定新的账期/运行目录；不要将目录设为已有原始数据目录。

```text
billing-download/
├── request.json
├── cost-details/
│   ├── ActualCost/2026-08-01_2026-08-31/
│   │   ├── manifest.json
│   │   ├── part-0001.csv
│   │   └── part-0002.csv   # 若服务端返回多个分片
│   └── AmortizedCost/2026-08-01_2026-08-31/
│       ├── manifest.json
│       └── part-0001.csv
├── actual/Actual_2026-08-01_2026-08-31.csv
├── amortized/Amortized_2026-08-01_2026-08-31.csv
├── invoices.json
├── invoice-id-issues.csv
├── invoice-reconciliation.csv
├── validation-summary.json
└── invoice-documents/       # 指定 --download-invoices 时
    ├── index.json          # 发票 ID 到本地文件名的映射
    └── invoice-0001.pdf
```

原始 CSV 分片保留下载内容；`manifest.json` 保存请求、状态和分片信息，
将签名 `blobLink` 替换为本地文件名，避免保存 SAS 凭据。默认不再生成整月
`Actual.json` / `Amortized.json`。`NoDataFound` / HTTP 204 记为空数据集且校验不通过。
失败状态、错误结构、缺失分片、截断下载、非法 CSV 不生成成功报告。

最终 CSV 保留原始字段，并忽略表头大小写和空格，为流水线补充规范列名，包括
`invoiceId`、`ResourceId`、`costInBillingCurrency`、`billingCurrency`、`reservationId`、
`benefitId`、`pricingModel`、`chargeType`、`meterCategory`、`tags` 等。
支持 `Cost` / `Currency` / `BillingCurrencyCode` 等别名，不使用 USD 或定价币种费用
替代账单币种金额；金额从 CSV 字符串直接转 `Decimal`。
Tags 可为 JSON 对象或不带最外层花括号的键值对，统一输出 JSON 对象；非法标签会报错。
发票记录总是保存到 `invoices.json`；`--download-invoices` 额外下载每张发票的默认
文档（PDF 或 ZIP，按内容确定扩展名），并非逐个下载全部税务附件。
下载 URL 生成支持 202 轮询，
`--invoice-download-timeout` 默认 600 秒；单次 HTTP 请求超时为 120 秒。
ARM API 的 429/部分 5xx 最多请求 5 次，其他 API 错误直接抛出。
重试同时遵守 `Retry-After` 和 Consumption 的
`x-ms-ratelimit-...-retry-after` 秒数，取最大等待值；超过 600 秒时明确报错，
避免提前重试导致持续限流。
报表 Blob 下载不携带 ARM token、不跟随重定向；下载失败清理当前 `.part` 并报错，
不自动续传。报告链接过期时需重新生成报告。

`invoice-id-issues.csv` 给出 Actual CSV 行号（含表头）、记录定位标识、
缺失/未知发票 ID、币种和金额；`invoice-reconciliation.csv` 给出逐发票差额。
`validation-summary.json` 包含总体结论、币种汇总、空数据集以及未匹配发票。
报告出现 `passed: true` 才表示本次两项校验成功。

退出码：`0` 表示校验通过，`2` 表示完成下载但校验不通过（命令行参数错误也使用
`2`）；网络、认证、数据格式或文件操作异常非零退出并显示异常。
校验不通过仍保留全部已下载数据和差异报告；中途下载/解析失败可能留下部分文件，
但不会生成本次最终 `validation-summary.json`，不能据部分文件继续分摊。
这些文件包含敏感账单信息；默认 `billing-download/` 已被 Git 忽略，自定义输出目录
也应放在仓库外或自行加入 ignore，不要提交账单或上传给无权限人员。

校验通过后接入第一步：

```bash
python3 allocate_ri_difference.py \
  --actual "billing-download/actual/Actual_*.csv" \
  --amortized "billing-download/amortized/Amortized_*.csv" \
  --output-dir work/01-actual-reconciled
```
